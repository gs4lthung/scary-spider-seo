## Per task evidence

### T1.1 Single issue registry (ADR-0002)
Verifier acceptance:
- There are no hand-written counters left: `grep "let missingViewport" Overview.tsx` finds nothing. Overview now builds its sections from `ISSUE_DEFS` and gets its counts from `countIssues`.
- `filterPages(pages, filter, ctx)` takes 3 parameters (filters.ts:418).
- Deleting an `ISSUE_SOLUTIONS` entry makes `tsc` fail with TS2741 (checked in a temp copy).
- The registry tests pass (49/49 at the time), including `countIssues matches filterPages length for every key`. All 28 page predicates are identical to the old switch.

Visible behaviour changes:
- The duplicate title, meta and content tiles now count affected pages, not distinct duplicated values, so the numbers can be higher than before.
- The 4xx/5xx tile uses the predicate. It differs from before only for status 0 or 1xx.
- The detail modal lists issues in registry order.

Minor finding: the comment at `App.tsx:92` says "26 sub-filters", which is already out of date.

### T1.2 URL structure audits (ADR-0003)
Verifier acceptance:
- There are six new keys: `urlUppercase`, `urlUnderscores`, `urlParameters`, `urlOver115`, `urlNonAscii` and `urlMultipleSlashes`. Each has a Google Search Central solution.
- Vitest passed 73/73, including `urlNonAscii detects percent-encoded UTF-8 path` and `urlParameters ignores a bare trailing question mark`.
- `url_audit_fixtures_are_crawled_verbatim` passes: `/URL_Page.html?ref=nav` and `/a//b.html` both return 200 and their URLs are unchanged.

Minor findings:
- URL cells now show decoded text (`decodeURI`), so bidi and zero-width control characters in crawled URLs are shown too. This could be used to spoof a URL visually. It is not an XSS risk.
- Search still matches against the encoded URL, not the decoded text shown in the cell.
- The 2xx/3xx guard is not tested at 399 and 400.

Design notes:
- `urlOver115` measures the full URL, host included.
- Spaces and other percent-encoded ASCII characters get no key yet. A possible later key is `urlEncodedCharacters`.

### T1.3 Title/meta length and pixel width (ADR-0004)
Verifier acceptance:
- There are eight new keys: `titleOverPixels`, `titleUnderPixels`, `titleSameAsH1`, `metaTooLong`, `metaTooShort`, `metaOverPixels`, `metaUnderPixels` and `h1TooLong`, each with a solution.
- The "Title px" and "Meta px" columns are in the Pages table.
- The pixelWidth tests pass, including "a 60 character typical title lands between 450 and 600 px".
- `title_equals_h1_fixture` passes.

No findings. The widths come from Helvetica/Arial AFM metrics. Thresholds are strict, and a missing title or meta description is not also flagged as short. The new columns were not checked visually in the running app.

### T1.4 Directive and canonical audits (ADR-0005)
Verifier acceptance:
- There are eight new keys: `missingCanonical`, `canonicalised`, `canonicalToNonIndexable`, `canonicalToRedirect`, `directiveNoindex`, `directiveNofollow`, `directiveNone` and `xRobotsTagPresent`.
- These tests pass: `canonicalToNonIndexable flags a page whose canonical target is noindex`, `parseRobotsDirectives handles bot prefixes and spacing` and `directive_and_canonical_fixtures`.

Minor findings:
- `pageByUrl` and `canonicalStatusMap` hold the same data, which means two O(n) map copies per UI flush (defer to T4.2).
- `xRobotsTagPresent` parses the header without caching on every recount.

Follow-up: the crawler's own indexability check only looks for the substring `noindex`. A page with `robots=none` is therefore still shown as Indexable, although `directiveNone` flags it.

- These tests pass: `notInSitemap is silent when no page came from a sitemap` and `notInSitemap skips the start URL`.

### T1.6 Content, depth, size and redirect target audits (ADR-0007)
Verifier acceptance:
- There are five new keys:
  - `lowWordCount`: fewer than 200 words, on 2xx HTML pages.
  - `deepPage`: depth greater than 3.
  - `largeHtml`: HTML larger than 1 MiB.
  - `internalRedirect`
  - `redirectToError`
- Vitest passed 128/128 with tests on both sides of each threshold.
- `redirect_to_gone_reports_final_404` passes.

Minor findings:
- `lowWordCount` and `deepPage` do not exclude redirected URLs, so the destination's content is counted twice.
- `internalRedirect`, like `orphanPage`, depends on `linkedUrls`. That set only arrives with `crawl://done` and is not saved with a crawl, so the count shows 0 during a live crawl and after loading a saved crawl. Persisting `linkedUrls` would fix this and is a candidate follow-up.

Note: `prettier --check` warns on `filters.ts`, `filters.test.ts` and `issueSolutions.ts`. Prettier is not part of the gate.

### T1.7 Bulk issues export (ADR-0008)
Verifier acceptance:
- The "Export Issues" dropdown has two items, "Export issues…" and "Export issue summary…". Both call the new `save_text_file` command.
- These tests pass: `quotes commas quotes and newlines`, `neutralises formula injection`, `one row per page issue pair` and `summary counts match countIssues`, plus 2 Rust tests.
- No new dependency: the dropdown uses the `radix-ui` package that was already installed.

Minor findings:
- `save_text_file` writes text supplied by the webview to any path. With `csp: null`, a future script injection would become arbitrary file write. No injection path was found today. Suggested fix: allow only the `.csv` extension, or use the fs plugin scope.
- The formula-injection prefix does not cover a leading `\t` or `\r`.
- `issueExport.ts` repeats the scoped issue-definition lists that are private to `filters.ts`, so the logic exists twice.
